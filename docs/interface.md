# FinSentry 模块交接规范 v0.1（2026-09-28）

此文件是团队约定，不是程序 API 服务，也不是模型训练数据。**本文件优先于之前三份任务书中不一致的字段名和旧版 R1。** 变更须先由团队确认，再由项目负责人改版本号、样例和测试；代码成员按同一版本实现。

## 范围与状态

本周：一家公司的一份年报，本期 2025 年和该报告披露的上期 2024 年比较；先用团队样例测试程序，待原年报核对后才作正式分析。异常状态仅为 `PASS`（规则未触发）、`REVIEW`（值得进一步核验）、`DATA_ISSUE`（必需数据缺失/重复、单位或口径不可比、上期为零等无法计算）。`PASS` 不等于公司没有风险，`REVIEW` 不等于造假。

## Skill 1：结构化财务数据 → 筛查结果

输入文件 `data/sample/financial_data.csv`（正式运行将用 `data/processed/financial_data.csv`），UTF-8 带表头，**一行 = 一个指标在一个年度的一个值**。固定列：

| 列 | 含义与约定 |
| --- | --- |
| `metric` | 四个固定名称：`营业收入`、`归母净利润`、`经营活动现金流量净额`、`扣非后归母净利润` |
| `year` | `2025` 或 `2024`，整年，不填季度 |
| `value_original` | 年报中原始金额，纯数字，不包含千分位逗号 |
| `original_unit` | 原始单位，如 `千元`；同一指标两期必须可比 |
| `value_yuan` | 原始金额换算成元，如千元乘以 1000；用于程序计算 |
| `statement_scope` | `合并`；不要混入母公司报表 |
| `source_file` | 年报文件名；两年的对比值可均来自同一份年报 |
| `source_page` | 团队记录的页码；正式引用前核对 PDF 物理页与印刷页 |
| `page_verified` | `true` 或 `false`；样例尚未人工对照 PDF，均为 `false` |

同比增长率：`(本期值 - 上期值) / abs(上期值)`；如果上期值为零则 `DATA_ISSUE`。对样例四个正的上期值，这与通常的 `(本期-上期)/上期` 相同。未来遇到亏损转盈等负基数案例，须由财务负责人决定是否改用方向判断及其他表达，不直接沿用百分比规则。

本周三条规则（20 个百分点均为**MVP 暂定阈值**，不是法规或造假判定标准）：

- `R1` 收入—利润背离：营收同比 `< 0`，归母同比 `> 0`，归母同比减营收同比 `>= 20` 个百分点。
- `R2` 利润—现金流背离：归母同比 `> 0`，经营现金流同比 `< 0`，前者减后者 `>= 20` 个百分点。
- `R3` 扣非前后背离：归母同比 `> 0` 且扣非同比 `< 0`，或两者同比增长率的绝对差 `>= 20` 个百分点。

如果影响某规则的任一金额上期不大于零、缺字段、重复、口径/单位不匹配，则该规则返回 `DATA_ISSUE`，不得强行计算结论。缺失扣非字段只影响 R3，不应挡住 R1/R2。

Skill 1 的输出文件 `outputs/screening_result.json`。固定顶层字段：`schema_version`、`case_id`、`data_status`、`results`。`results` 中每条规则固定字段：`rule_id`、`status`、`calculation`、`reason`、`source_pages`、`source_verified`。`calculation` 用对象保存数值，增长率为小数（例如 `-0.018` = `-1.80%`），增速差是百分点（例如 `65.71`）。除字典已有规则外不得自行新增结论。详见 `data/sample/expected_screening_result.json`。

样例 `source_page` 是来自团队表格、未核对原 PDF 的标记。因此程序可以展示待核页码，但 `source_verified=false`；**不允许据此在正式报告里声称已经追溯到原 PDF**。

## Skill 2：筛查结果 + 年报文本 → 候选证据

第一周 Skill 2 尚未实现。检索模块交付时约定每条证据含：`rule_id`、`question`、`quote`（逐字原文）、`pdf_page`（核对过的 PDF 物理页）、`printed_page`（如有）、`source_file`、`support_level`。证据等级固定为 `DIRECTLY_SUPPORTED`、`RELATED_EVIDENCE`、`INSUFFICIENT`，最后一个表示不能支持当前解释。只有核对了原文和页码，才可从候选证据进入正式报告。

DeepSeek 不计算同比、不生成页码、不补写缺失原文；只根据 Skill 1 输出和 Skill 2 已检索的证据规划调查并组织谨慎解释。没有可靠证据时标注证据不足、待人工复核。任何流程都不作财务造假认定或投资建议。

## 路径与提交

代码不得写 `C:\\Users\\某人\\...` 之类个人绝对路径。函数优先接收 `Path` 参数，由 `run_demo.py` 根据 `Path(__file__).resolve().parent` 定位项目根目录。代码成员提交文件时须同时交运行命令、依赖版本和至少一个通过/一个异常输入测试。队友可以只发文件给项目负责人，由负责人统一验收并提交 GitHub。
